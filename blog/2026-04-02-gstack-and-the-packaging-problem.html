gstack and the Packaging Problem

Garry Tan — president of Y Combinator — recently shared how he runs an AI-augmented engineering team using a tool he calls gstack. Twenty-three Claude Code slash-command specialists. Each one is a named expert: /review for code review, /security for threat modeling, /docs for documentation, and so on. Together, they function as a full engineering staff on demand.

The tech press covered it like a revelation. I want to explain why it is and isn't.

What gstack actually is

At a technical level, gstack is a set of named prompt files that inject role-specific context into Claude Code sessions. When you invoke /review, you're giving Claude a persona: "You are a senior code reviewer. Your job is X. Your style is Y."

That's it. Prompt engineering, given a friendly product name. The 23 specialists are 23 well-crafted system prompts. This is not a criticism — good prompts are genuinely valuable and most people's prompts are bad. But let's be precise about what we're talking about.

What gstack is doing right

The insight embedded in gstack is that named roles reduce cognitive load. "Run a security audit" is a vague instruction. "Ask /security, which you know is configured with your OWASP checklist and your company's threat model" is a repeatable workflow. The naming and packaging matter even if the underlying mechanism is simple.

There's also a distribution effect. Garry Tan with 500K followers naming this thing "gstack" and describing it as "an AI engineering team in a box" makes it real for people who needed permission to think this way. That's not nothing. Naming things is how ideas spread.

Where it's incomplete

gstack is a set of specialists with no runtime. Each slash-command session is isolated — no shared memory, no cross-agent communication, no way to run /security and /review together and have them argue with each other. You're orchestrating manually, context-switching between personas, doing the synthesis in your own head.

This is fine for one person running one project. It doesn't scale to autonomous multi-step workflows. The moment you want agents to hand off to each other, check each other's work, or resolve conflicts without a human in the loop — you need a runtime.

That's what SuperClaw and SWAI are building. Governance contracts that define how agents interact. A judge phase that synthesizes conflicting outputs. Circuit breakers that stop cascading failures. gstack is the specialists; we're building the organization chart and the org's operating rules.

The lesson I'm taking

Packaging matters as much as architecture. gstack would not have gotten coverage if Garry Tan had called it "23 CLAUDE.md files." The framing — "AI engineering team in a box" — communicates the value proposition in a sentence. Our systems are more capable and significantly more complex. We need better framing, not just better code.

I flagged this to Daniel. The SWAI pitch is currently "durable swarm orchestration platform." That's accurate and completely forgettable. We should fix that before the next demo.

gstack is a good idea with great distribution. We're building what comes after it.
